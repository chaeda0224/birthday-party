# 생일 파티 v0.1.0 독립 검증 보고서

**판정: 현재 소스의 공동 모드 출시는 보류.** 종료 뒤 늦게 도착한 응답이 삭제된 프로필을 화면에 복원하는 경합을 재현했다. 음향과 불기의 전환에도 앞선 중지 확인을 재사용하는 경로가 남아 있다.

## 출시 전 수정

1. **종료한 방의 프로필이 다시 나타남 — 재현.** [remote.ts:65](../src/session/remote.ts#L65)의 `apply`는 현재 세션이 종료됐는지 확인하지 않는다. [125–129행](../src/session/remote.ts#L125)에서 종료 응답을 적용하지 않고 기존 revision을 유지한다. 메모리 모의 RPC로 상태 조회를 먼저 시작하고, 종료를 완료해 프로필이 비워진 뒤 이전 조회 응답을 풀었다. 동일 revision의 `lit` 상태와 프로필이 돌아왔다. `PartySession`은 [53행](../src/app/PartySession.tsx#L53)의 종료 화면에서 다시 일반 화면으로 바뀔 수 있다. 종료를 되돌릴 수 없는 상태로 만들고, 종료 시점에 대기 중인 상태·프로필·사진 응답을 모두 무효화해야 한다.
2. **음향 재준비가 중지 확인을 무효화하지 않음 — 소스 확인.** [0002:88](../supabase/migrations/202611060002_review_hardening.sql#L88)의 `ready`가 음향 임대를 갱신하면서 같은 제어 버전의 기존 `stopped` ACK를 남긴다. [15행](../supabase/migrations/202611060002_review_hardening.sql#L15)의 불기 조건이 이를 받아들인다. [PartySession:42](../src/app/PartySession.tsx#L42)의 주기적 `ready`도 같은 RPC를 쓴다. `ready`가 이전 확인을 무효화하도록 하고, 불기 단계에서는 음향 임대를 다시 발급하지 않는지 함께 확인한다.

## 빠른 출시 게이트

- 두 문제를 수정하고 종료 후 늦은 응답을 무시하는 회귀와 `stopped → ready → blow` 거부를 재실행한다. 사진 정리 Cron을 활성화하고 1회 실행 성공을 확인한다. API의 사진 삭제 통과는 Storage 객체의 실제 정리까지 입증하지 않는다.
- 최종 Pages 번들로 브라우저 두 세션에서 생성→초대 입장→점화→버튼 소등→축하→종료를 한 번 수행한다. 한 세션을 잠깐 숨겼다가 복귀시켜 호스트 복구를 확인하고, 종료 후 두 화면의 이름·사진이 지워진 채로 유지되는지 본다. 최종 빌드와 공개 산출물 점검도 같은 버전에서 실행한다.
- **NOT RUN:** 실제 모바일 흔들기·마이크 권한/감지, 기기 간 Realtime 반영과 폭죽 시각 편차 계측, 실제 Cron에 의한 Storage 정리, 최종 3D 렌더링과 공개 Pages 재검증. 물리 센서를 출시 기능으로 검증 완료라고 표시하려면 지원 모바일 기기에서 한 차례 직접 확인해야 한다. 원계약 QA 46개 전체를 실행한 결과가 아니다.

기록에는 식별 값, 토큰, 사진 주소, 원시 로그를 넣지 않았다. 보고서 외 파일과 원격 환경은 변경하지 않았다.
